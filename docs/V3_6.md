# 麦麦最新改版 v3.6.0

v3.6.0 更专注于把群聊整理清楚：重要的事情会写得完整一些，普通话题也会保留下来；时间、参与者、链接和引用会再次核对，无法确认的内容不会当成事实写进日报。

日报只送到管理员私聊，不会在来源群里发进度、结果或报错。

[打开 v3.6.0 下载页](https://github.com/artinsteinbrecher-lab/MaiBot-private-daily-analysis/releases/tag/v3.6.0)

## 它会整理什么

一份日报分成两部分：

- **主要事件**：记录事情的经过、结果、待确认内容、相关成员、链接和可回查原话；
- **普通事件**：页面中也叫普通话题，按时间列出标题和一句话说明，不会挤占主要事件的位置。

它还会：

- 先给管理员发送一份可以搜索的文字目录；
- 再把主要事件整理成分页图片；
- 把普通事件整理成带时间的文字列表；
- 处理失败时重试，仍然缺少内容就明确写出“部分完成”；
- 保留 `/mysummary`，但只生成人物的事实型小结，不再提供 MBTI、金句排行或娱乐评级。

## 先选安装包

v3.6.0 有两个安装包，总结核心完全相同。

### 普通版

[下载普通版](https://github.com/artinsteinbrecher-lab/MaiBot-private-daily-analysis/releases/download/v3.6.0/khiqwq_daily_analysis-v3.6.0-standard.zip)

适合只想直接使用的人。它跟随 MaiBot 当前的默认回复模型，不修改 MaiBot，也不需要设置四个模型任务。

### 多模型版

[下载多模型版](https://github.com/artinsteinbrecher-lab/MaiBot-private-daily-analysis/releases/download/v3.6.0/khiqwq_daily_analysis-v3.6.0-multimodel.zip)

适合希望不同模型分别负责读取、整理、复查和人物小结的人。它比普通版多带一个 `extras` 工具目录；没有应用这个工具时，它的用法和普通版相同。

不知道该选哪个时，先选普通版就好。

## 普通版怎么安装

1. 下载普通版 ZIP，然后解压。
2. 把解压出来的插件文件夹放进 MaiBot 的 `plugins` 文件夹。
3. 重启 MaiBot，或者在插件页面重新加载它。
4. 在 WebUI 中启用插件，填写要总结的群、日报接收 QQ 和管理员 QQ。
5. 管理员私聊麦麦发送 `/summary 群号 今天`。

常见 Docker 安装里的插件位置是：

```text
./data/MaiMBot/plugins/
```

放好后，插件文件夹里应该直接能看到 `plugin.py`，不要多套一层同名文件夹。

看到开始提示、处理进度、日报和完成提示都出现在管理员私聊，就说明安装成功。普通版到这里已经完成，不需要运行 `extras` 里的任何工具。

## 多模型版怎么安装

### 第一步：先把插件装好

先按照普通版的五个步骤安装多模型 ZIP，并成功生成一次日报。

这时四项工作都跟随 MaiBot 默认的 `replyer` 模型。插件已经能正常使用，只是还没有分别分配模型。

### 第二步：检查 MaiBot 能不能修改

多模型工具需要指向真正的 MaiBot 源码根目录。这个目录里应该同时存在：

```text
src/config/
src/llm_models/
```

它不是插件目录、数据目录或 Docker Compose 文件所在目录。

进入插件的 `extras` 文件夹，先执行只读检查：

```bash
python3 install_maibot_task_routing.py /path/to/MaiBot --check
```

检查结果：

- `pristine`：当前版本可以应用；
- `installed`：已经完整安装，不要重复处理；
- `unknown`：版本无法确认，停止；
- `partial`：发现只改了一部分，停止并人工检查。

当前工具只支持模型配置版本 `1.17.6` 的干净源码，或者已经由它完整升级到 `1.17.7` 的状态。看到 `unknown` 或 `partial` 时不要强行覆盖。

### 第三步：备份并应用

只有检查结果为 `pristine` 时才执行：

```bash
python3 install_maibot_task_routing.py /path/to/MaiBot --apply
```

工具会先建立备份，再加入四个插件专用模型任务。请保存命令输出的 `BACKUP_DIR`，以后需要恢复时会用到。

### 第四步：让修改真正生效

按原来的部署方式重新构建或重新创建 MaiBot 核心容器。只重载插件不够，因为这一步修改的是 MaiBot 本身。

完成后再次运行：

```bash
python3 install_maibot_task_routing.py /path/to/MaiBot --check
```

看到 `installed`，再进入 WebUI 分配模型。

### Docker 环境特别注意

如果使用现成的只读镜像，而且宿主机没有 MaiBot 源码，不要直接在一次性容器里执行 `--apply`。容器重建后，改动会消失。

这类环境需要选择一种可保留的做法：

- 用修改后的 MaiBot 源码重新构建镜像；
- 把工具修改的文件作为持久化文件挂载进容器；
- 暂时不启用多模型分工，继续跟随默认模型。

## 四个模型任务是什么

完成多模型修改后，MaiBot 的高级模型任务中会出现：

- `plugin_daily_extract`：读取消息，找出事件、时间、成员和证据；
- `plugin_daily_compose`：合并重复内容，把事件整理成好读的日报；
- `plugin_daily_verify`：复查事实，只删除没有依据的内容或降低完成状态；
- `plugin_user_profile`：生成有消息依据的事实型人物小结。

模型供应商、地址、Key 和模型名称都在 MaiBot 中设置，不要填进插件配置。

某一项不填写时，会自动跟随 `replyer`。可以先只给一两项分配模型，不需要一次全部填完。

## WebUI 里需要设置什么

主线只需要这些：

1. 在“插件”中启用；
2. 在“自动总结”中填写来源群和日报接收 QQ；
3. 在“管理员账号”中填写允许操作的 QQ；
4. 在“事件日报”中选择完整覆盖或均衡抽样；
5. 保存设置。

完整覆盖会尽量处理全部有效文本，适合正式日报；均衡抽样更快，适合先试运行。

喜欢直接修改文件时，可以参考安装包内的 `config.example.toml`。平时使用 WebUI 即可。

## 静默功能去了哪里

v3.6.0 不再内置群聊静默。它只保证日报插件自己不会向来源群发送进度、结果或报错，不会阻止 MaiBot 和其他插件正常回复。

如果只想让麦麦安静地待在群里，可以搭配从本项目分离出来的 **麦麦群安静插件**。它只负责安静，与日报分别设置。

如果希望总结、娱乐化个人小结和静默仍然放在一个插件里，可以继续使用[麦麦安静写书 v3.1.0](LEGACY_SILENCE.md)。

v3.1.0 与 v3.6.0 使用同一个插件身份，不能同时安装。切换前先备份并移走旧版本。

## 安装完成后怎么确认

- 日志中能看到插件已经加载；
- 管理员私聊 `/summary 群号 今天` 后能收到进度和结果；
- 来源群没有出现日报进度或结果；
- 日报同时保留主要事件和普通事件；
- 多模型版的 `--check` 显示 `installed`；
- 没有单独分配模型的任务确实回退到 `replyer`。
