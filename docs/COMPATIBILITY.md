# 兼容性与版本边界

这份说明专门回答“什么环境可以装、哪个版本需要改 MaiBot”。

## v3.6.2 兼容基线

- MaiBot Host：`1.1.0+`
- maibot_sdk：`2.x`

| 项目 | 最低建议 | 当前验证基线 |
| --- | --- | --- |
| MaiBot | 1.1.0 | 1.1.0 |
| maibot_sdk | 2.0.0 | MaiBot 1.1.0 内置 SDK 2.x |
| Python | 由 MaiBot 宿主决定 | 3.13 |
| 平台 | MaiBot 能正常连接 QQ | Ubuntu + Docker + NapCat |

插件启动时还会检查实际需要的 `ctx.*` 能力；宿主虽然满足版本号，但缺少发送、
消息读取、渲染或模型调用能力时，会明确拒绝加载并写出缺失项。

## 三个发行版本

### 麦麦安静写书 v3.1.1

旧核心的禁言整合维护包。保留旧的静默行为和趣味个人总结，只加入发送顺序修复，
不跟随 v3.6.2 新核心。
与 v3.6.2 使用同一个插件身份，不能同时安装；升级前应备份配置并移走旧目录。

### 麦麦认真写书 v3.6.2 standard

只需安装插件目录，不修改 MaiBot 源码。四个内部流程统一跟随 `replyer`，因此模型供应商
和模型 ID 由 MaiBot 统一管理。

### 麦麦一起写书 v3.6.2 multimodel

复制插件目录即可按 standard 工作。只有在实际生效的 MaiBot 源码树上通过 `extras/`
脚本检查并应用补丁后，才会出现四个插件专用高级任务。补丁不匹配时必须停止，不要强行
修改宿主源码。

## 模型与供应商边界

插件只请求 MaiBot 的统一 LLM 能力和具名任务，不保存供应商 URL、Key 或模型 ID。
OpenAI、Gemini、DeepSeek 等兼容层的差异由 MaiBot 模型配置处理；插件本身不假定某个
供应商一定支持特定参数。

## 遇到不兼容时

插件加载时会检查关键能力。缺少必要接口时会直接记录缺失项并停止加载，避免定时日报
运行到一半才失败。先升级 MaiBot/SDK；如果不需要多模型分工，可以改用 standard，绕过
宿主高级任务补丁。
