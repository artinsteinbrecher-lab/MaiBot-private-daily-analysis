# 总结核心评估与版本选择

评估日期：2026-08-02。选择标准依次为真实性、完整性、可读性、失败可见性和安装边界；成本不作为主要约束。

## 版本能力矩阵

| 能力 | 旧服务器导出 | v3.2 | v3.3 / v3.3.1 | v3.5.1 / v3.6.0 |
|---|---|---|---|---|
| 全量完整覆盖 | 否或有限 | 是 | 是 | 是，且新安装默认启用 |

## 共同最优组合

最终选择不是简单回退到某个旧版本，而是保留各阶段已经验证的有效设计：

- v3.2：完整覆盖、分片重试、二分恢复、部分完成和失败范围。
- v3.3：轻量话题索引、本地合并、只精炼主要事件、普通话题文本时间线。
- v3.3.1：主要事件图片渲染或发送失败后的事实型文本回退。
- v3.5.1：四职责流程、逐声明证据绑定、编排禁止增事实、删除式复核、娱乐功能清理。
- v3.6.0：把上述核心固定为两版共同实现，并将新安装默认设为“完整覆盖 + 完整详情”。

## 放弃的方向

- 不保留 MBTI、情绪指数、趣味称号、金句排行、压抑指数和活跃轨迹。
- 不在插件设置中重复保存供应商、URL、API Key 或模型 ID。
- 不使用 v3.4 的 `daily_topic_scan` / `daily_event_refine` 两任务方案作为最终接口。
- 不通过删减模型步骤来换取普通版安装便利；两版的总结核心和质量约束保持一致。
- 不把公开榜单直接当作真实群聊总结胜负；模型分配只是接入后的初始路由，仍需同源 A/B。

## 结论

两版都选择 3.6.0 作为共同总结核心。普通版的区别只有“固定跟随 `replyer`”；增强版只增加
MaiBot 四任务独立路由能力，不增加娱乐分析，不改变报告结构，也不降低任何事实约束。
